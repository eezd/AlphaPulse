# 关键词词表与重要性校准

2026-11-15。本轮为本地实现；不改写历史分析，不发布线上 Skill，不调用真实模型。质量以检索准确性、核心信息覆盖、事实和归属正确、评分有依据为准，不以 Token 数量判断。

## 词表范围和维护

`backend/src/alphapulse/briefings/data/lexicon/` 保存固定来源、覆盖规则、生成结果及 Unicode 许可证；运行时不联网。当前 **8,602 条**，主要为 SEC 的 **7,997 个 CIK 公司主体**，加 CLDR 国家/地区、货币及人工维护的机构部门、加密资产、指数、技术和动作。它不是全球证券主数据：公司英文名覆盖较广，中文译名、非美公司及证券产品仍需持续维护；未知词保留原文，不猜测映射。

- SEC：`https://www.sec.gov/files/company_tickers.json`，快照时间、来源 SHA256 见 `sources/manifest.json`。以 CIK 合并公司名，不把股票 ticker 当公司别名。复用说明见 `https://www.sec.gov/about/webmaster-frequently-asked-questions`，来源本身不保证完全准确。
- CLDR：Unicode CLDR JSON **48.0.0** 的 en/zh territories/currencies；保留 `UNICODE-LICENSE.txt`。不把所有两字母国别码或三字母货币码自动当原文实体；USD/EUR 等显式加入。
- `overrides.json`：维护规范中文名和安全别名，不能把集团、研究部、执行办公室合并；SEC/CLDR 覆盖ID必须真实存在。来源更新后审阅别名冲突及条目差异，再显式升级生成器版本。

```sh
python3 scripts/build_briefing_lexicon.py
python3 scripts/build_briefing_lexicon.py --check
```

生成器校验每个来源摘要，按稳定顺序生成；不得直接修改 `lexicon.json`。包内固定词表 SHA256 与处理规则版本写入每篇分析审计。

## 处理边界

1. 分析前在完整原文中匹配候选，最多提示80个，显式记录总数和截断标记；原文不裁剪，候选不是强制标签或新事实。长名称优先，英文词边界阻止 ETH 匹配 ETHUSDT，存在多个实体的同名别名不自动选择。“金/银”等单字不用于正文自动匹配，避免命中“资金/银行”；euro area、Euro-zone、欧元区不作为欧元资产补全。
2. 保存前保留模型原始关键词，只剔除不在标题、摘要或正文**同一字段中连续逐字出现**的别名，记录原值及原因；不自动补造替代别名。任一关键词剔除后没有别名则整篇失败。事实和关键词的 `quote` 仍严格逐字校验，不能通过过滤绕开。规范名与过滤后别名共同指向同一条目才统一。证券与公司角色冲突、未知产品或机构归属冲突保留**过滤后的**结果并记录待核查项；不把外部词表的译名塞进逐字别名。
3. 仅从模型已选事实的原文引文补回已知资产/技术主题，例如欧元、美元、HBM4e。处理规则 `keywords:v3` 沿用完整名称保护，基于过滤后保留的完整别名：Ethereum Classic、Bitcoin Cash 内部不再拆出 Ethereum、Bitcoin，同一引文中独立出现的基础资产仍可补全。全文未被模型选中的命中只列入审计候选，不把所有背景对象加入标签；这仍不能保证语义覆盖完备。`assets` 的资产清单仍由模型判断，程序不凭币种出现就伪造持仓/行情。
4. `Analysis.rules.keyword_processing` 保留模型原始关键词、逐条别名剔除决定、规范化决策、补全依据、未选候选及词表/处理版本；成功结果只存过滤后的别名，分数不由词表改写。冲突导致整组保留时仍只返回过滤后的结果并记录冲突，审计不宣称该组已应用。历史成功版本不重算。
5. 已知完整名称搜索扩展至该条目的规范名与别名，查询与历史JSON元素均按 NFKC、Unicode casefold、空白折叠后作相等匹配；数据库使用 PostgreSQL 18 的 `casefold`/`pg_unicode_fast`。未知关键词沿用原有字面搜索。历史结果无需重算或回填。高盛研究部的查询不会仅因名称前缀就匹配高盛集团。

## 重要性口径

单篇以原文发表时已知信息评价研究价值；首次采集时间和归档方式不改变档位，准入时效由程序控制。分时/日报以窗口结束前已有证据沿用相同档位标准，新增正式决定/更正/反证才有调整依据。预测与未兑现状态要披露，不能仅用“历史资料/尚未验证”扣分；也不能把未经支持的巨大假设当系统性事实升星。

保留 20/40/70/90 星级阈值。先选择背景、有限、实质、重大、系统性档位，再给档内分数。理由说明范围、规模、期限、渠道、新增信息及状态条件；分报事件调整须在 impact 说明新依据。统一规则通过 `config.system_prompt()` 加入三阶段有效系统提示并冻结到 rules；已有发布内容不被写回修改，未来运行即使绑定旧 Skill 也使用统一附加规则。候选三份文本含同一规则，组合时不重复追加。

以下是**合成参照案例及建议区间，尚未经用户逐例确认或真实模型验证**。它们用于定位分歧，不是客观唯一真值；案例全部字段应冻结，变体只改指定字段。旧模型输出不是金标。

| 案例 | 固定材料／变化 | 建议范围 | 判断依据与不变量 |
| --- | --- | --- | --- |
| A1 | 某机构播客简介仅列AI、选举话题，无观点、数据或转录 | 0–19 | 背景目录；不补造策略 |
| A2 | 已公开预测原文重发，全文明确没有新数据或修改 | 0–19 | 无新增；若材料本身含重大首次信息，应另判 |
| A3 | 小型企业单店调整营业时间，无其他经营影响 | 20–39 | 局部具体变化 |
| A4 | 单个小市场税务申报表更新，无税率或适用范围变化 | 20–39 | 有操作影响，不能写成重大税改 |
| A5 | 研究根据订单下调某存储品类下一季度价格预测，列供需原因和反证 | 40–69 | 行业实质信息，预测条件保留 |
| A6 | 欧洲盈利展望解释海外收入、欧元与美元折算、6–12月传导滞后；未声明大幅修订 | 40–69 | 关键机制有价值；保留币种与期限，不因知名机构自动四星 |
| A7 | 全球展望列多国增长及油价条件预测，无明确此前基准或新增冲击 | 40–69 | 广覆盖不等于重大新变化；若补充重大修订证据须重新判断 |
| A8 | 原文给出此前基准、最新重大供给中断数据，将多个主要经济体预测大幅下修并解释传导 | 70–89 | 范围、修订及新增证据明确；不能只因属于预测降档 |
| A9 | 主要央行公布正式利率决定及后续框架，对广泛融资和资产定价有直接作用 | 70–89 | 决定、时间与广泛影响明确；不凭正负方向调档 |
| A10 | 监管就广泛资产发行提出实质豁免征求意见，规模/条件明确，仍需审议 | 40–69 | 制度研究价值，但现实适用范围未生效；不是所有提案都只能三星 |
| A11 | A10同一政策正式实施，材料确认覆盖主要市场、立即改变融资准入 | 70–89 | 状态带来现实渠道变化；不能只把“提案”换词就机械升档 |
| A12 | 主要国家支付清算体系已广泛中断，官方确认规模、持续时间和实体交易影响 | 90–100 | 已支持的系统性变化；不要补造金融崩溃或价格路径 |
| A13 | 匿名帖猜测“可能全球停摆”，没有规模、证据或可核实机制 | 0–39 | 不将极端假设当已发生事实；保留传闻状态 |
| V1 | A5/A7原文与发表日相同，仅first_seen改为一个月后、mode改archive | 与原例同档 | 不能用回补和旧文身份扣分 |
| V2 | A8只替换机构名称，证据、条件、覆盖范围相同 | 与原例同档 | 不按机构名气加权 |
| V3 | A9改为方向相反但相同幅度、范围与政策机制的正式决定 | 与原例同档 | 利好利空不等于重要性 |
| V4 | 同一事件无新证据进入period、period_map/reduce、daily，或增加三条转载 | 与原例同档 | 不累计分数、不按重复报道加分 |
| V5 | A12后续官方更正为单一银行短暂维护，其他系统正常 | 应低于原档 | 新证据确实缩小范围；报表说明更正与分数变化 |

校准时记录：原文/输入摘要、完整系统提示摘要、词表版本、原始与处理后输出、建议档位、模型档位、判断理由、审阅者、pass/fail/uncertain。70和90边界要复核上一档必要依据，允许有理由的区间分歧。仅提示词包含这些规则不代表模型已经遵守。
